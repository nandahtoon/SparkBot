Chapter 1 accessible entry preserved. React shell/App currently owns session/UI; later extract one campaign controller with explicit entry, pause, completion and exit transitions. M01 introduces read-only buildMainGameSnapshot in src/game/mainGameFoundation.ts: delegates to adventureMap, missionCurriculum and levels, preserves 24 mission IDs, existing unlock/star rules, recommended level, learning goals. No new save schema, route, reward or UI. Profile roster/storage stays authoritative. No competing progress store.
- Domain: existing engine/simulator/levels + reviewed deterministic spatial rules; same goal semantics in 2D/3D, no frame-dependent rules. Typed commands, outcome, feedback; adapters per mechanic, not copied simulators.
- Presentation: existing Three.js world controller; one active renderer and input owner, accessible 2D fallback, no automatic experimental screen. Character rig and identity reused; form abilities only after gameplay parity review.
- Learning: existing curriculum, visual goal, optional speech, direct play and coding practice distinct; feedback without automatic solution, safe retry.
- Persistence: existing SaveProfile and roster, offline PWA, preserve IDs and stars; future migrations require explicit versioning, idempotence, rollback and legacy fixture tests. Experimental local saves are not imported automatically.
- Clubhouse: seven activities remain playable as existing optional features; expansion HOLD. No new standalone arcade/3D Room, ads, login, analytics or child identifiers. No new external assets/dependencies.
- Audio, reduced motion, touch/keyboard and portrait/landscape are cross-cutting requirements. Preserve current behavior.
